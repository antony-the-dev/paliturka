Каталог

Ціна Наша: опт + націнка за правилами з config/pricing.json. Опт до вітрини не потрапляє взагалі. Наявність stockNp > 0 означає «відправимо сьогодні». Якщо книжка лише на віртуальному складі, пишемо «під замовлення» з deliveryTime. Фільтри Перебудова сітки анімована: картки пливуть на нові місця, а не стрибають.

Як це працюватиме

Шлях від каталогу постачальника до посилки в руках читача.

  1. Каталог постачальника

    API BookTicket B2B віддає назви, авторів, ціни опт і роздріб, залишки по складах і посилання на обкладинки. Сторінками по 100 книжок.

    GET /commerce/price-list?skip=0&take=100
{
  "count": …  // скільки всього, побачимо після вивантаження
  "data": [{
    "productId": 103398,
    "name": "Ми тебе любимо, Зайчику",
    "authorName": "Мона Авад",
    "publisherName": "ЖОРЖ",
    "retailPrice": "570",
    "wholesalePrice": "371",
    "stockNp": 411,
    "stickers": ["єКнига", "Хіт Продажу", …]
  }, …]
}
    справжній запис з API, скорочено

  2. Щоденна синхронізація

    Скрипт уночі оновлює ціни й залишки, додає нові книжки й ховає ті, що зникли. Якщо щось обірвалось, продовжує з місця зупинки.

    $ python bookticket_sync.py catalog
06:00:01  Токен взято з auth.json
06:00:01  Нове вивантаження #12
06:00:02    [ 10%]  …
06:02:31    [ 60%]  …
06:04:40  Каталог готовий
06:04:40  Сховано 12 книг, яких більше нема
$ python bookticket_sync.py covers --in-stock
    так виглядатиме щоденний запуск, цифри умовні

  3. Вітрина

    Пошук, добірки, фільтри, картки книжок і кошик. Покупець бачить лише нашу ціну і зрозумілий термін.

    Ми тебе любимо, ЗайчикуМона Авад570 ₴

    Відправимо сьогодні

    stockNp: 411 → «відправимо сьогодні»

  4. Щоденне замовлення

    Раз на день усі замовлення клієнтів збираються в одне замовлення постачальнику через його API. Книжки приїжджають у магазин у Ніжині: звідти клієнт забирає сам або отримує Новою Поштою.
